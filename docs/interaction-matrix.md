# Zero — interaction matrix (what-triggers-what)

The single place that answers "when the user does X to a [kind] entity in [state], what
happens (and what's the guard)?" Use it to check a NEW request against existing behaviour
BEFORE building — if a request contradicts a CURRENT row, flag it; if it fills a PROPOSED
row, cross-check the TODO ledger.

Status tags: **[CUR]** = built + verified today · **[PART]** = partially built ·
**[TODO]** = proposed/awaiting decision (see TODO ledger).

## Vocabulary
- **kinds**: soul · individual · organism · community · space · resource · task · moment · instant.
- **states** (`getState().word`, one axis, mutually exclusive; kinds.ts): `open` → `complete`
  → `closed`; plus `ongoing`, `cancelled`, terminal `dead`/`retired`. `open` includes a
  reopened entity. `scheduled` now applies to EVERY plannable kind: an entity with a concrete
  FUTURE start reads `scheduled` (only the timeless Soul, the one non-plannable kind, stays
  `open`) — an action kind renders it "scheduled", a being renders it "expected".
  LIFE-BEINGS add `alive`: INDIVIDUAL is alive once its `bornAt` has passed; ORGANISM / COMMUNITY
  are alive once PUBLISHED (`publishedAt` set & past — the Publish toggle is their birth). Arc:
  open → scheduled → alive → dead/retired/closed. A Close while alive ⇒ `dead` (individual/
  organism) / `retired` (community), age = anchor→close; while not-yet-lived ⇒ plain `closed`.
- **axes/fields** (v0.2.228 RENAME — the plan reads in DATE words, the record in tense words):
  `schedule{startDate,endDate,at,dueDate,duration,sessions[],plannedOccurrences[]}` · `closeAt` (frozen
  close instant) · `closePolicy` ('manual' opts out of auto midnight-close) · `completed` (task done
  scalar) · `color` (was `accent`) · `displayTitle` (universal fetched/display label — was the
  URL-only `webTitle`; still auto-filled only for a `webUrl`) · `priority`/`requested` (now UNIVERSAL,
  on every kind) · `taggedContextIds` (multi-parent links) · `creationDate` (was `createdAt`)/`ownerId`/
  `createdBy`. `sessions[]` (the RECORDED clock) uses TENSE names — entries are `{startedAt,endedAt?,via?}`
  (a session HAPPENED). `plannedOccurrences[]` (v0.2.229 RESHAPE — they are the PLAN, actual is derived;
  RENAMED from `occurrences` v0.2.233) uses PLAN names `{start,end?,cancelled?}` — a temporally-NEUTRAL
  list of when the entity occurs/occurred (past-vs-future = `start` vs now, never stored). SCALAR-COLLAPSE
  (v0.2.232, was Option A): the scalar `startDate`/`endDate` is now purely a MIRROR of the CURRENT primary
  = the soonest NON-cancelled span across {scalar + plannedOccurrences[]}; `resyncPrimary(schedule)` (in
  data.ts) re-picks it after every occurrence write, so EVERY occurrence — the primary included — is cancellable and the
  ~53 scalar readers/`getState`/timeline stay unchanged (they still see "current primary + the rest, no
  overlap"). `blocks[]` (a planned sub-span) KEEPS `{startAt,endAt}`. RECURRENCE-AS-A-LAYER (v0.2.234):
  a `repeat` rule (`schedule.repeat`) is NEVER materialised — the series is projected FRESH at view-time
  by `projectOccurrences(e,now,cap=10)` (data.ts), which merges the three occurrence layers into a
  start-ordered list of lightweight `OccurrenceRecord`s (`{entityId,start,end?,origin,cancelled,occIndex,
  recurrenceId?}` — a row opens the PARENT entity, it is NOT an entity). Layers: (1) DEFINITE = scalar
  primary + `plannedOccurrences[]`; (2) RULE = `repeat` expanded from the anchor over upcoming local days
  (DST-safe day-stepper, capped at `cap`); (3) `schedule.exceptions{[recurrenceId]:{cancelled?,start?,end?}}`
  = restore-able patches on rule-days, keyed by the occurrence's LOCAL-MIDNIGHT day-key (a cancelled entry
  = an EXDATE tombstone; clearing it un-cancels; `start`/`end` reserved for future per-occurrence time edit).
  For a recurring entity the scalar is the rule ANCHOR (a stable seed, emitted as one rule row) NOT a mirror,
  so `resyncPrimary` EARLY-RETURNS when `repeat` is set (scalar/`getState`/`plannedStart` untouched). Both
  layers may co-exist on one entity; same-day collisions render BOTH (definite sorts first — no auto-supersede).
  The §0 block and the future occurrence-centric dayline are meant to consume this ONE projection so they
  can't drift. (The legacy `getTimelineOccurrences` entity-clone expander is UNTOUCHED — it still feeds the
  doomed current dayline until the dayline rework swaps it onto the projection too.)
  EFFECTIVE END (`effectiveScheduleEnd`, kinds.ts): declared `endDate`, ELSE concrete
  `startDate`+`duration` (minutes) ⇒ IMPLIED end. Persisted old-key data is migrated on load
  (`migrateStoredScheduleFields`, in-memory; localStorage rewrites on next mutation).
